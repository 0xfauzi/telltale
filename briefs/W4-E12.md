Traps:
- Blinding is the experiment. The reviewer's working directory holds ONLY the material
  files of one session in one arm, under neutral names (protocol.md "Material"), and
  the prompt names no task, session, arm or date. A prompt that leaks the task id
  invalidates the run: check the material files for the task id string before each
  launch (`grep -c W4- material/*`; the raw stream will contain it in the brief text,
  which is unavoidable and is recorded, not scrubbed: the raw arm is the raw arm).
- FOREGROUND ONLY; never end your turn while a reviewer runs. `--permission-mode
  bypassPermissions` is mandatory. `--max-turns 60`.
- The reviewer's answer text is parsed for a JSON object with the ten keys and stored
  in out/answers.json together with the score. Nothing else the reviewer wrote is
  stored anywhere.
- Arm S material is produced by `telltale show`, `telltale timeline` and `telltale
  vector` on the OWNER'S store for the capture ids in manifest.json, run read-only
  (TELLTALE_HOME unset, no `rebuild`, no `outcome`). Arm R material is the archived raw
  file under experiments/E12/out/raw/ (ask the orchestrator if it is missing; do not
  rebuild it from ~/.claude).
- Each reviewer runs under the launcher with `--task-id E12-<n>-<S|R> --attempt 1
  --experiment E12` so its cost is a capture; the harness reads wall and tokens from
  `telltale show` of that capture, never from the reviewer's own words.
- Never write under ~/.claude or ~/.codex; never edit a global config.
