DO:
(1) importer_git.py: `import_history(store, repo_path, *, branch=None, since=None, level, checks=True) -> dict`. One capture per repository: capture id = importer.capture_id("git", repo_id) where repo_id is what repo.identity(repo_path) reports, so the same clone always lands in the same capture and two clones of one remote do too (repo_id already hashes the remote; measure that on a temp clone and paste it). Emit, in this order, through the same append path the other importers use: telltale.capture_started (provider "git", argv_shape "backfill", surfaces_configured ["git_history"], content_level, plus `git_branch` and `git_since` if the allowlist takes them, else nothing), telltale.repo.identity (repo.identity as the launcher emits it), then per commit the two or three observations of (2) to (4), then telltale.capture_ended with `surfaces_received: {"git_history": <commits>}`.
(2) Per first-parent commit on the branch (default: the repository's HEAD branch; `git log --first-parent --format=%H`, oldest first), one telltale.repo.commit with the payload repo_link builds for the launcher (sha, parents, tree, committed_ts as ISO 8601 UTC with offset, files_changed, additions, deletions, per_file) and `link_confidence: "unlinked"`. "unlinked" is a new word: it means "no capture was ever linked to this commit, by construction", which is a different statement from "heuristic" (a link somebody attempted). Put it in the allowlist ENUM if the value is checked. provider_ts = committed_ts.
(3) Per commit, when `checks` is on and `gh` is on PATH and the remote is a GitHub URL: one external.outcome of kind mechanical_verification with external_system "github:check-runs", component_id = sha, external_run_id = the check suite id when the API gives one else the sha, status "pass" when every check run's conclusion is one of success, neutral, skipped and "fail" when any conclusion is one of failure, timed_out, cancelled, action_required, startup_failure, duration_ms = max(completed_at) minus min(started_at) over the runs in whole ms, timestamp = max(completed_at); when the commit has 0 check runs, or any run has no completed_at, emit NO outcome and count it (`no_check_runs`, `check_run_incomplete`) in the capture_ended payload. Never guess a status from a missing field. The gh call is one process per commit with a 30 s timeout; a non-zero exit or unparsable JSON is one diagnostics row (kind parse_failure) and no outcome. Rate: measure the wall time per call on the telltale repository and paste it; with `--no-checks` the import does no network at all.
(4) Per commit, the rework label from git alone: for commit i (first-parent order), take its diff against its first parent with `git show --first-parent --format= --unified=0 <sha>`; the ADDED lines per file (stripped, longer than 3 characters). For each of the next three first-parent commits j in (i, i+3], its REMOVED lines per file, same normalisation. If any file has a non-empty intersection, emit one external.outcome of kind revert_or_repair with external_system "git:line-overlap", component_id = sha of i, external_run_id = sha of j (the first j that hits), status "reworked", timestamp = committed_ts of j. Emit nothing when no j hits, and nothing when fewer than three later commits exist yet (the label is undecided, not 0). Byte-safe: decode diffs with errors="replace" (a chopin commit has a non-UTF-8 byte at position 80691 and the orchestrator's first scan crashed on it). Binary files ("Binary files differ") contribute no lines.
(5) Re-import: read the shas already recorded under this capture (`select json_extract(payload,'$.sha') ... where capture_id=? and observation_type='telltale.repo.commit'`), append only the commits not in that set, and re-evaluate the rework rule for the last three previously recorded commits (their windows may have closed since) emitting an outcome only where none exists for that sha. A second import immediately after the first appends 0 observations and says so. `--dry-run` prints commits found, commits new, check runs to fetch, and writes nothing. `--since DATE` limits the log; the default is the whole branch.
(6) cli_import.py: kind "git-history" with `--repo PATH` (default: the current directory's repository), `--branch`, `--since`, `--no-checks`, `--dry-run`. Refuse a path that is not a git repository and a repository with no commits, by name.
