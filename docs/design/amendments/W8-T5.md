# W8-T5: path-derived commit cells survive the payload bound

Amends design 6.12, "Change clock", 6.8's commit statistics and 6.3's
`telltale.repo.commit` payload. One change to where the three path columns are computed,
four fields on one allowlist entry, and one clause struck from a cohort sentence.

## 1. The three path cells are folded at record time, not at build time

`subsystems_touched`, `test_files_changed` and `dependency_delta` are the three columns of
design 6.12 that are questions about PATHS rather than about counts. W3-T4 put a `per_file`
list on the commit payload and `series_paths.columns` answered all three from it at series
build time.

That put the answer behind a bound that has nothing to do with the question. Design 6.4
caps a payload at 8 KB, and both writers fit a commit to it by cutting `per_file` to a
prefix and setting `per_file_truncated` (`importer_git._capped`, `launch._capped`).
`series_paths` then refuses a prefix, correctly: a prefix that happens to hold no test file
does not mean the commit changed none. So the three columns went unknown on exactly the
largest commits, and one unknown cell makes a column `partial`, which readiness check 1 and
`backtest._variant` exclude BY NAME.

**The rule.** `repo_link._commit_stats` folds the three cells itself, by calling
`series_paths.columns` on the WHOLE `per_file` list it just built, before any caller fits
the payload to the bound. They go on the payload beside `files_changed`, which has been the
true count whatever the bound did to the list since W3-T4. When the list is unknown (a merge
reached with no parent chosen, a diff git could not read) the three stay None, as they were.

`series_paths.columns` prefers the stored cells when the payload carries all three, and
falls back to the `per_file` rule otherwise. The fallback is the live path for every commit
recorded before this amendment, which on the owner's store is every launcher capture taken
so far. All three or none: a payload holding two of them is a shape the reader refuses
rather than completes.

Nothing about the RULE moved. The two ways to the answer agree wherever both can speak,
measured below.

## 2. `path_rules_version` on the payload

A short hash of `series_paths.py`'s source, computed the way `correlate.REDUCER_VERSION` and
`series.REDUCER_VERSION` are: a hash of the rule rather than a number somebody remembers to
bump. `repo_link.PATH_RULES_VERSION`, spelled `paths-<12 hex>`.

It is on the row because a cell is now stored rather than recomputed. Before this
amendment, editing `_TEST_GLOBS` or `_MANIFESTS` changed every column of every series built
afterwards and the series id moved with it. Now an edit changes what LATER commits store and
leaves earlier rows as they were, so a frame can hold cells folded by two different rules,
and without this field a reader holding both could not tell.

Twelve hex characters, 48 bits. What it must separate is the number of distinct versions of
one small module a store ever holds, not an adversary.

## 3. The allowlist entry

`telltale.repo.commit` gains four fields and nothing else:
`subsystems_touched`, `test_files_changed` and `dependency_delta` as `Kind.SIZE`, for the
same reason `files_changed` is SIZE (a value that is not a number is dropped rather than
carried), and `path_rules_version` as `Kind.ENUM`, a short symbolic string bounded at 64
characters.

The two fit-to-bound functions are unchanged in behaviour: both rebuild the payload as
`{**payload, "per_file": kept}`, so a scalar passes through the cut untouched. This is the
launcher path too. `repo_link.commits_since` returns the whole list from inside the process
and `_Capture.emit` applies `_capped` and then the sanitizer afterwards, so the fold happens
strictly before the bound on both writers.

## 4. `NO_PATHS` loses its truncation clause

The cohort sentence for an unknown path column said the list was "recorded before W3-T4, or
a merge, ... or a list the 8 KB payload bound truncated". Truncation is no longer a cause on
its own. The sentence now names the two that remain: the recorder had no list to fold (a
merge, or a diff git could not read), or the commit was recorded before this amendment and
the list it would be recomputed from is absent or was truncated.

## What was measured

A temporary `$TELLTALE_HOME`, `telltale import git-history --repo <R> --no-checks` then
`series build --clock change --repo <id>`, on 2026-09-06. Before and after are the SAME
store, built twice: the "before" build ignores the stored cells, which is exactly the state
of the rule before this amendment.

| repository | rows | nulls in each of the three, before | after | rows whose list the bound truncated |
| --- | --- | --- | --- | --- |
| deckgen | 118 | 5 (`partial`) | 0 (`observed`) | 5 |
| kstrl (`~/Documents/code/ralph`) | 252 | 4 (`partial`) | 0 (`observed`) | 4 |
| telltale | 177 | 0 (`observed`) | 0 (`observed`) | 0 |
| systemap | 108 | 0 (`observed`) | 0 (`observed`) | 0 |

The nulls were exactly the truncated rows. All six candidate features of E16 are now
`observed` on all four repositories.

**The two rules agree.** Over every commit whose stored list is COMPLETE, the stored cells
compared against `series_paths.columns` folded over that list alone: 0 disagreements out of
N = 113 (deckgen), 248 (kstrl), 177 (telltale), 108 (systemap); 646 commits in total.

**What a prefix would have said.** The five deckgen commits the bound truncated, with the
stored cells beside the fold over the prefix that survived, as
(subsystems, test files, dependency):

| commit | files changed | entries kept | stored | fold over the prefix |
| --- | --- | --- | --- | --- |
| `552ef3ad3186` | 101 | 85 | (2, 0, 1) | (2, 0, 0) |
| `92e3c567bb84` | 140 | 88 | (6, 5, 1) | (4, 0, 0) |
| `6607d927f94f` | 85 | 78 | (7, 10, 0) | (6, 5, 0) |
| `f55fb868f435` | 115 | 83 | (7, 8, 0) | (5, 0, 0) |
| `b4ba2ff0d523` | 94 | 87 | (8, 22, 1) | (6, 20, 0) |

This is why `series_paths` refused a prefix and why the refusal was right: on
`92e3c567bb84` the prefix says the commit changed no test file and touched no manifest, and
it changed five and touched one. The answer is not to read the prefix more bravely. It is to
ask the question where the whole list is.

## What this does not do

It does not change what any of the three cells MEAN: the rule is `series_paths` in both
places, and the 646-commit agreement above is the check. It does not backfill: a commit
recorded before this amendment carries no cells, and reaches them through the `per_file`
fallback or not at all. It does not remove the bound or raise it, and a truncated `per_file`
list is still a truncated list for any reader that wants the paths themselves.
