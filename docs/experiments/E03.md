# E03: does TimesFM 3.0.0 install and run on this machine, and what does one forecast cost?

Why this matters (30 seconds): design 6.12 builds the whole forecasting laboratory on a
model that has never been run here. Four claims depend on this experiment. That the
`forecast` extra resolves on Python 3.12 at all, because the collector's zero-dependency
rule means the model stack only ever arrives through that extra. That a backtest is
affordable, because the backtester calls `predict_batch` once per origin and a run has
tens of origins. That the adapter's refusal to pass NaN is a real guard rather than
superstition, because the forecaster interpolates internally and would silently accept
what the adapter refuses. And that `device="cpu"` is the right pin, because design 6.12
pins it "unless E03 shows MPS works" and this is the machine that decides.

## Decision rule, written before the run

Recorded before the first `uv sync --extra forecast` of this experiment and committed
ahead of `experiments/E03/run.py`, which did not exist when this section was written.

- **(a) Installation.** If `uv sync --extra forecast` fails on Python 3.12, report the
  resolver error verbatim and propose the smallest change: a different torch pin, or
  Python 3.11 for the extra alone. The runtime dependency list is not touched either way.
- **(b) Per-call cost.** If a horizon-64 forecast on one 64-point univariate context takes
  more than 60 s on CPU and MPS is unavailable or wrong, the backtester must batch every
  origin of a run into one `predict_batch` call, and the wave 2 backtest brief carries the
  measured per-call cost. Under 60 s, per-window calls are affordable and the measured
  number goes into the brief.
- **(c) The NaN guard.** If a context with NaN produces output differing from the same
  series with the NaN linearly interpolated by less than 1e-6 absolute, the forecaster's
  internal interpolation is confirmed and the adapter's `np.isfinite` assertion is what
  keeps a silent imputation out of a predictive claim. If the difference is larger, record
  it: the adapter still refuses NaN, and the reason changes from "it imputes silently" to
  "it does something else with NaN that we have not characterised".
- **(d) The device pin.** If MPS output differs from CPU output by more than 1e-3 relative
  on any point, `device="cpu"` is pinned in the adapter. Otherwise MPS is allowed, and the
  measured speed factor is what justifies it.
