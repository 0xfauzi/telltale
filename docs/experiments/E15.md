# E15: which questions about a coding-agent session can be predicted from what Telltale records, and which cannot?

Why this matters (30 seconds): E07, E08 and E13 asked one question of the data, "how many
tokens will the next request spend", and the answer was that a rolling median is as good
as a foundation model, because E08 showed the ORDER of per-request amounts carries almost
no information. That is one question, about the least structured quantity in the store.
An exploratory scan on 2026-09-05 (experiments/E15/scan.py, numbers below) found three
kinds of structure the lab had never tested: failures cluster, the session's level is
knowable early, and work has phases. This experiment tests each as a pre-registered
prediction task with honest nulls, so that what Telltale can and cannot predict is a
list of measured answers rather than one negative about tokens.

## Prior evidence, from the scan (in-sample, descriptive, NOT the test)

Owner's store copy at experiments/E13/out/home/telltale.db, Claude captures.

- Verification runs with a known result: 5,869; base failure rate 0.045. After a failed
  run the next run fails with probability 0.303; after a pass, 0.032.
- Sessions with at least 32 model requests: 594. Spearman rank correlation between the
  output tokens of the first 16 requests and the output tokens of everything after: 0.724;
  between the median output tokens of the first 16 and of the rest: 0.823. Between the
  context size at request 16 and the total number of requests: -0.039.
- Tool activities in sequence (command, file_read, file_edit, verification_run): base
  entropy 1.147 bits; conditional on the previous kind 0.938 bits, an 18.2 percent
  reduction. After a file_read, the next activity is a file_read with probability 0.49;
  after a file_edit, a file_edit 0.46; after a verification_run, a command 0.61.
- Command success is known on 83,499 of 83,786 command activities; 2,376 failed (0.028).

These numbers were looked at before the rules below were written. The rules use
conventional bars (10 percent skill, AUC 0.70) rather than bars tuned to the scan, and
every result below comes from folds the model never saw.

## Decision rule, written before the run

Four tasks. Each has a prediction TIME (what is known), a TARGET, two NULLS, one simple
MODEL, and one bar. Evaluation is 5-fold cross-validation grouped by capture (a session is
entirely in one fold; fold = sha256 of the capture id modulo 5), per cohort
(claude/import and claude/launcher, never pooled across; Codex enters when W7-T1 gives it
a request clock). Every metric is computed on out-of-fold predictions pooled over the five
folds, and per fold; a task passes only if the pooled number clears the bar AND every
fold's skill is above zero.

1. **V: this verification run will fail.** Time: the run starts. Known: the previous
   run's result (failed / passed / none yet), runs since the last failure, the run's
   category (test, typecheck, lint, other) and scope, and the counts of file edits,
   distinct files edited, commands and model requests since the previous run, and the
   run's ordinal in the session. Nulls: the base rate of the training folds; persistence
   (predict the previous run's result). Model: L2 logistic regression. Bar: AUC at least
   0.70 and Brier skill at least 0.10 against the better null.
2. **C: this command will fail.** Time: the command starts. Known: whether the previous
   command failed, failures among the last five commands, the command's category, edits
   since the last command, whether it is a verification run. Nulls and model as V. Bar as V.
3. **L: how much the rest of the session will spend.** Time: after request 16. Targets:
   log of the output tokens of requests 17 onward, and log of the number of requests
   remaining (sessions with at least 32 requests, so the target is never empty). Known:
   log sum and log median of output tokens, fresh input tokens and cache-read tokens over
   the first 16 requests, the tool mix of those 16 (edits, reads, commands, verifications,
   failures), the model and effort. Null: the training folds' median target. Model: ridge
   regression on standardised features. Bar: MAE skill on the log scale at least 0.10
   against the null and Spearman at least 0.50 out of fold.
4. **P: what kind of tool activity comes next.** Time: after each tool activity. Target:
   the next activity's kind among command, file_read, file_edit, verification_run. Null:
   the training folds' base rates. Model: the lag-1 transition table (and lag-2, reported
   beside it, never chosen after the fact). Bar: log-loss reduction at least 0.10 against
   the base rate.

Labels. A task that clears its bar is "predictable at this n"; one whose pooled metric
clears the bar but a fold does not is "unstable"; otherwise "not predictable from these
inputs", which is a finding about the inputs, never about the session. The claim class of
every number is predictive, the coverage is that of the activities read, and nothing here
says why: a failure that follows a failure is a description of the sequence, not a cause.
Words refused in the output: cause, impact, would.

was started and no token was spent. Store: the copy at experiments/E13/out/home/telltale.db

## What it means

Two of the four questions have a measured yes on the owner's own sessions, one has a
"we can rank but not act", and one has a no.

- **How much the rest of a session will spend is knowable by request 16.** The model's
  error is 44 percent below the best guess made without looking (the typical session),
  and its ranking of sessions by spend is right with rank correlation 0.70. The typical
  miss is still a factor of three on the remaining output tokens, so this is a coarse
  estimate rather than a number to bill against. Remaining request COUNT is weaker (a
  factor of 1.7 typical miss, rank 0.48) and falls just short of the bar.
- **What the agent does next is patterned.** Knowing the last activity kind cuts the
  log-loss by 18 percent (24 percent with the last two). The gain in plain accuracy is
  small (77 to 79 percent) because "another command" is the answer most of the time;
  the structure is real, the practical value is modest.
- **A failing verification can be ranked but not called.** Out of fold the model orders
  runs by risk better than chance (AUC 0.74) and better than "same as last time"
  (0.59), but failures are 3 percent of runs and the probability estimates barely beat
  the base rate (Brier skill 3 percent). The one strong fact is descriptive: after a
  failure, the next run fails 30 percent of the time against 3 percent otherwise.
  Command failure is the same story, weaker.

Against E07, E08 and E13: the request clock's amounts were the wrong target, not the
wrong model. The session's LEVEL is predictable across sessions and the per-request
noise around it is not, which is exactly why a rolling median tied a foundation model.

## What we rejected

- That TimesFM lost because it is the wrong model. E15 used no sequence model at all for
  the two positive results: a ridge regression on 16 requests of features and a
  transition table. The structure is cross-sectional and categorical, not temporal amounts.
- That "AUC 0.74" makes verification failure a product feature. The Brier bar was written
  before the run precisely so that a rare event with a useful ranking but useless
  probabilities is not oversold; it did not clear.
- That the launcher cohort contradicts the import cohort on L. At n = 49 sessions the
  launcher result is noise around zero in both directions (MAE skill -0.09 and +0.04);
  the import cohort's 545 sessions are the measurement.

## How sure we are

- L (remaining spend), P (next kind): measured, out of fold, every fold positive, on one
  person's sessions. Whether it holds for another person's sessions: unknown.
- V, C labels: measured. That better inputs (diff size, test scope, the failing test's
  name) would change them: judgement; imports carry no repo snapshots.
- The scan's numbers were seen before the rules were written; the bars are conventional
  and the results are out of fold, but a second person's store is the real replication.
