# Task log

One file per task, `<TASK>.md`, written by the implementer that did the work and merged as
part of that task's change. A report here is IMMUTABLE once merged: it is the record of what
one task knew, measured and got wrong at one moment, and a later task that edits it destroys
the only evidence of how a decision was reached. When a later task finds a report's claim to
be wrong, it says so in its own report and names the file it corrects; the wrong claim stays
where it is, which is what makes the correction legible. The order is fixed (OUTCOME, WHAT
WAS WRONG, WHAT CHANGED, UNSURE OR NOT DONE, NEXT, then EXPLAIN FOR THE OWNER) so that the
two sections that matter most to somebody who was not there, what broke and what is still
unsure, cannot be buried.
