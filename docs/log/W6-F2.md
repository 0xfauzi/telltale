# W6-F2 preserve Codex tool outcomes on masked checks

The Codex reducer now retains tool outcomes when a shell chain masks its verification
result. The timeline reports `failed, check masked` for a stated tool failure. It
reports `ok, check masked` for stated success. An unknown outcome remains `check masked`.

The reducer previously skipped `_outcome` whenever `exit_masked` was true. This removed
the tool result together with the verification result. Claude already kept these
facts separate in `activities_tools._tool_outcome`.

The fix removes that conditional. The separate guard still removes the verification
exit code. `measures_intervals.failed` still returns unknown before reading tool success
on masked runs. No provider observation changes.

## Reproduction and verification

`uv run pytest tests/integration/test_codex_masked.py` sends synthetic Codex OTel records
through the real HTTP receiver. The real store, reducer, measures, and CLI timeline
process them. The cases supply tool success, tool failure, and no stated outcome.

Before the source change, two cases failed and one passed in 0.97 seconds. Both
stated outcomes disappeared from the timeline, which displayed only `check masked`.

The final cases also supply rollout exit code 1 alongside each stated tool result.
The observations retain that exit code. Verification activities omit it and retain
`exit_masked`. Failed-test and fail-to-pass counts remain unknown. Their warning names
the masked verification run.

Replacing the fixed reducer with its original version produced two failures and one
pass in 0.36 seconds. A `finally` block restored the fixed source. The same command
then passed all three cases in 0.34 seconds.

## Limits

The inputs use the provider shapes already recorded in Codex CLI 0.150.1 fixtures.
These checks test recorder behavior. They do not execute the represented shell command
or claim a result for its masked check. No paid session ran.
