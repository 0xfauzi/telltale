## WHAT WAS WRONG

- The brief's own VERIFY line for the badge check assumes Markdown-style
  `[text](url)` badges; this README's badges are raw HTML `<img>`/`<a>` tags, so the
  literal `grep -o 'https://img.shields.io[^)]*\|...'` pattern captures the URL plus
  trailing HTML up to the next literal `)`, which does not exist until end of tag,
  producing garbage tails. Adjusted to `grep -oE '...[^"]*'` (stop at the closing quote
  of the `src`/`href` attribute instead), which extracts the seven URLs cleanly. Same
  intent, correct extraction for this file's actual markup.
- `scripts/check_links.py`'s first draft matched briefs/W6-T5.md:66 as a broken link:
  this brief's own DO(1) text quotes the link syntax literally,
  `` `[..](path[#anchor])` ``, wholly inside one inline-code span. A link checker that
  cannot tell a literal code example from a real link is wrong about every repository
  that documents Markdown syntax in Markdown, which this one does. Fixed by stripping
  inline code spans (`` `[^`]*` ``) from each line before matching, which does not
  affect real links because a real link's target always sits in the parenthesised part,
  never inside the backticks that only style the link text.
- `EXEMPT["spec/media"]` being closed over every file with no discriminating field made
  the first draft fail mypy strict (`Call to untyped function (unknown) in typed
  context`): the dict's value type did not name a return type until annotated
  `dict[str, Callable[[Path], bool]]`.
- `check_index_counts`'s first version checked `str(count) in index_text`: a plain
  substring test. For counts of 1 or 2 digits this is nearly always true by accident
  (`"512"` and `"32"` both contain `"2"`), so it would pass without anyone writing the
  count anywhere. Changed to a word-boundary regex, `re.search(rf"\b{count}\b", text)`.
  This is still a soft heuristic, not a proof (a `v0.2` heading already satisfies `\b2\b`
  on its own), but it rejects the specific accident found and is stated as a heuristic
  below rather than oversold as a check.
- `scan()` and `main()`'s first drafts failed the `complexipy --staged` gate (cognitive
  complexity 16 and 23 against the limit of 15): pre-commit's advisory named the exact
  lines. Split into `check_link()`, `check_index_counts()` and
  `check_index_completeness()`; the gate now passes clean, and the split also made the
  three responsibilities (link resolution, count-per-pattern, reachability) separately
  testable by inspection.
- The v0.1 and v0.2 gate reports (`docs/gates/wave-1.md`, `wave-2.md`) carry no single
  "met" or "not met" sentence for the whole wave, unlike waves 0 and 3 through 6: they
  assess each spec criterion in its own subsection. Read every criterion in both files
  rather than guessing a verdict: v0.1's four criteria and v0.2's four criteria are each
  demonstrated (the last two of v0.2, H2 and H3 real-session floors, only by the E05
  re-run and E06 sections appended later in the same file), and neither file states a
  failure anywhere. Ticked both, citing the file; this is the report's own reading of
  the evidence in each file, not a quotation, and is named as such here in case the
  owner reads it differently.

## EXPLAIN FOR THE OWNER

Three things changed for a stranger who lands on this repository the day it goes public,
and one thing did not change because it cannot yet.

**The README stopped promising and started reporting.** Every earlier wave's README said
what a future wave would add ("wave 0 replaces this stub", "wrapping a session... arrives
in wave 1"). All of that is now the present tense, checked against the real CLI on the
day: the Quickstart is the actual transcript of `uv sync`, `telltale doctor`,
`telltale run` wrapping a plain shell command, `sessions`, `show`, `timeline` and
`explain`, run in a fresh clone under a temporary home directory so nothing borrowed from
this machine's own installed state. A new Commands table lists all 23 subcommands
`telltale --help` prints today, one line each, copied rather than described from memory,
so it cannot drift the way the old "two commands exist today" line did after 22 more
shipped underneath it.

**The documentation got an index a machine checks, not one a person remembers to update.**
`docs/README.md` used to link a handful of files by hand and miss the rest silently: no
row for `docs/gates/`, one template row standing in for 12 experiment write-ups, one
missing design guide. The new pre-commit hook, `docs-links-resolve`, makes that
structurally impossible from here forward: it fails the commit if a file under `docs/`
exists that the index does not link (with three named exceptions - the specification's
figures, the two brand PNGs, and the 55 task-log reports - which the index instead states
a count for, and the hook checks that the count is the true one). It also fails if any
relative link in the README, the contributing guide, the security policy, a doc, or a
brief points at a file that is not there, or at a `#heading` that does not exist in the
target. This is the kind of thing that only breaks quietly, in a rendered page, months
after the commit that broke it; now it breaks loudly, at commit time, with the exact
`file:line: target` that is wrong.

**The changelog now says what happened, not what wave 0 hoped would happen.** It listed
one task, from the very first day, for the whole build. It now lists all 59 merged pull
requests, in the order they merged, grouped under the wave whose exit criterion they were
built toward. The version stays `0.0.1` and unreleased: this task states what is true,
it does not decide when the project calls itself released, and nothing here cuts a tag.

**What did not change, and cannot yet: the CI badge.** The badge at the top of the README
points at a GitHub Actions workflow page that only resolves for people who can already see
this private repository; anyone else gets a 404, which I confirmed just now with an
unauthenticated request. That is not a bug in the README, it is what a private repository
looks like from outside, and it fixes itself the moment the repository turns public: no
text change makes a gated page render early, and pretending otherwise with a hand-written
badge would be exactly the kind of claim this project exists to refuse elsewhere.
